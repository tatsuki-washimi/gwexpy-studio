# GWexpy Studio 0.1.0a1 trial readiness

This document defines the source, artifact, qualification, publication, and
human-trial contract for the wheel-based prerelease.

Participants can use conda and `pip`, but do not need Git, a source checkout,
an editable install, or a GitHub account.

## M1: public source identity

The private snapshot `S`, public commit `P`, and detached canonical manifest `M`
must satisfy `manifest(S) == manifest(P) == M`. The public source verifier reads
`P` directly and ignores only top-level `.git` checkout metadata.

Product code, tests, schemas, assets, packaging metadata, documentation, public
CI, and the trial workflows are included in the M1 public source.
M2 first builds and qualifies the wheel with those workflows. Private evidence, internal notes,
harness configuration, and local build products remain excluded.

## Existing native Ubuntu reference Release

The existing schema 3 Release is retained as an Ubuntu 24.04 x86_64 reference
validation artifact. Its tag and two assets remain immutable:

```text
gwexpy-studio-trial-<build-id>.zip
gwexpy-studio-trial-<build-id>.zip.sha256
```

Its Release title and body identify it as Ubuntu 24.04 x86_64 only, not qualified
for WSL2 or macOS, and not distributable to other platforms. It remains a
non-latest prerelease. The verifier keeps schema 3 as read-only compatibility.

The Ubuntu Qt GL preflight records `libEGL.so.1` and `libGL.so.1`
before remediation. If required, `libegl1` and `libgl1` are installed and the successful
post-remediation state is recorded.

## Schema 4 platform Releases

The build workflow accepts exactly `wsl2-ubuntu24` or `macos15-arm64`. The
participant assets are:

```text
gwexpy-studio-trial-wsl2-ubuntu24-<build-id>.zip
gwexpy-studio-trial-wsl2-ubuntu24-<build-id>.zip.sha256
gwexpy-studio-trial-macos15-arm64-<build-id>.zip
gwexpy-studio-trial-macos15-arm64-<build-id>.zip.sha256
```

Each schema 4 `TRIAL-MANIFEST.json` binds the target record, Build ID, source
manifest, wheel, architecture-specific constraints and resolution, platform
Quick Starts, and `Feedback.ja.md`. WSL2 includes Ubuntu 24.04 x86_64 and
aarch64 records. macOS includes only macOS 15 arm64 records.

The archive has one target-qualified root, fixed order, fixed timestamps, normal
files only, internal `SHA256SUMS`, and a filename-bound outer sidecar. The
verifier rejects duplicate or extra entries, missing files, absolute paths,
`..`, symbolic links, tampering, target mismatch, and architecture mismatch
without extracting the participant archive.

## Build and publish boundary

The build workflow has `contents: read` only. It uses a fixed source SHA, builds
one wheel per target run, resolves the native closures, runs hosted technical
gates, creates the participant pair, and separately uploads a non-release
qualification kit.

The publish workflow has `actions: read` and `contents: write` only. It requires
an explicit build run ID and the SHA-256 of the complete cross-platform
`QUALIFICATION-SUMMARY.json`. It selects one immutable Actions artifact, verifies
the build workflow, source SHA, artifact digest, target, archive, and sidecar
before and after download, and rechecks default-branch HEAD immediately before
publication.

The `trial-publish` environment has no required reviewers and a
default-branch deployment policy.
Explicit authorization occurs before manual workflow dispatch.

Tags are direct references to `P`:

```text
trial-wsl2-ubuntu24-0.1.0a1-p.<sha>-r<run>-a<attempt>
trial-macos15-arm64-0.1.0a1-p.<sha>-r<run>-a<attempt>
```

Each Release is `draft=false`, `prerelease=true`, `latest=false`, and contains
only the corresponding ZIP and sidecar. Post-publication verification checks the
REST and GraphQL state, downloads both assets again, and reruns the verifier.

## Physical technical qualification

Three configurations are mandatory:

```text
Windows 11 x86_64 + WSL2 Ubuntu 24.04 x86_64 + WSLg
Windows 11 ARM64  + WSL2 Ubuntu 24.04 aarch64 + WSLg
Apple Silicon arm64 + macOS 15 or later
```

The owner runs one qualification-kit command: `bash run-qualification.sh`.
The kit creates a temporary conda
Python 3.12 prefix and test state, installs with `--only-binary=:all:`, and drives
the GUI without manual use. Checks cover native architecture, WSLg or Cocoa,
Qt/OpenGL, display and scaling, clipboard, Linux/Windows/macOS Unicode and spaced
paths, Try Sample, Load, Crop, ASD, Save, Close, Open, recovery, worker exit,
shared-memory cleanup, Python export, and About Build ID.

Evidence is canonical JSON without path, username, or hostname. The summary
verifier requires both WSL architectures and macOS arm64, passing checks, correct
Build IDs and wheel hashes, and one source SHA. Both platform Release bodies
record the same summary digest. A source change requires both targets to be
rebuilt and all three physical configurations to be requalified.

## Cross-platform human trial

The human trial starts only after both platform prereleases pass qualification.
There are at least three first-time manual users, including at least two WSL2
users and at least one macOS user.

Every participant must install and launch unassisted and complete Save → Close →
Open. At least `ceil(2N / 3)` participants must finish the Welcome-to-completion
workflow within five minutes. P0 and project/recovery P1 counts must be zero, and
the same P1 root cause must not affect two people.

Installation time and Welcome-to-workflow time are recorded separately.
Review/Restore absence is not a failure; continuation is recorded if either is
shown. Participants report facts, and the trial owner assigns severity. If a
stop condition occurs, recruitment stops and the affected Release returns to
draft. A new unassisted gate uses new first-time users and a new source commit,
tag, and Build ID.

## Out of scope

PyPI, AppImage, DMG, signing, notarization, and a native Windows installer are
outside this trial contract.
